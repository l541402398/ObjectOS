## 交付范围与原方案对应

沿 A2 的组织控制面 / Local Worker 边界推进，没有跳到 A3 需求工作区或 A4 流程引擎。
本次为可独立运行的 **A2.2a 设备与授权检查点**，不是完整执行桥。

- 真实 PostgreSQL 设备登记、会话绑定、持有证明、心跳、暂停、撤销和权限校验。管理员可以
  停用设备；恢复需要所属账号和本机凭据。旧登记不能通过重试恢复已撤销权限。
- Main 使用 safeStorage 在请求前保存登记标识和随机凭据。Renderer / SQLite 不持有凭据。
  IPC 顺序处理，避免后台读取与人工操作冲突；读取仍经过组织上下文围栏。
- Runtime 单写 SQLite，保存本机身份、项目关联、目录授权及审计。关联需要 Main 系统窗口
  确认真实规范路径、相对目录、只读/写入权限、时长和调用上限；默认只读。组织服务只保存
  不透明工作区引用，不接收本机绝对路径。
- 越界、盘符/UNC、外部链接目录、确认前目录变化、重复跨组织关联会被拒绝。未知上传响应
  撤销本机授权并记录后续远端撤销；离线撤销在本机立即生效，恢复连接后同步。
- 退出/切换先持久化加密的本机撤销意图。Runtime 暂停不阻止退出账号，恢复后先清除旧授权。
- Settings 增加真实设备表、详情、关联表单、确认、失效/待同步状态，并收敛账号区占用。
  不显示伪造的任务、在线数据或能力。任务接收明确为“尚未启用”。

PostgreSQL 追加迁移 3，SQLite 追加迁移 37。前两次 PG 迁移与旧 36 次 SQLite SQL 保持原样，
旧 V18/V24 项目、任务和运行升级/恢复验证通过。Agent 绘图、依赖投影、聊天内页移除、全局
配色和受保护 Design Lab 在此检查点均未修改；manifest 记录了相关源码校验。
