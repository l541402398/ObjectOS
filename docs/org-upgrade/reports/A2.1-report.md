## Delivered

Real PostgreSQL catalog for Agent, Skill, MCP and Tool definitions; organization/project-private
visibility; drafts with expected revisions; immutable checksummed publication; field differences;
deprecation and irreversible revocation; explicit project version binding and compare-and-set
replacement/unbind. Publishing a new version never silently changes existing pins. Revoked pins
remain visible audit facts. SQL also prevents rewriting/deleting published history.

All mutations revalidate membership/permissions inside the organization lock used by A1 role
changes. Tenant/project IDs are not grants. Organization admins need their own project permission.
Agent Skill references cannot cross scope or bind unavailable versions. Structured definitions
share named credential references only; recognized secrets and URL credentials are rejected.
Free-form prose cannot be certified secret-free. Existing local definitions/Runs are untouched.

The real Settings asset tab uses the approved tokens, semantic table, inline editors/confirmations,
version comparison, permission preview, project pins and explicit error recovery. Main owns HTTP
and auth; typed IPC carries configuration only. Native graph/connection and chat-removal files
are unchanged. See ADR-0068, A2_IMPLEMENTATION.md and design/A2_ASSET_UI.md.

## Remaining scope

This is the independently runnable A2.1 catalog slice. Worker registration/capabilities/grants,
heartbeat/revocation/leases, local project links, AssetBindingResolver and frozen local Run snapshots
remain A2.2. Catalog bindings do not install MCP/Skills/Tools or launch execution. Remote unattended
execution, requirement workspaces and configurable lifecycle instances are not delivered here.

Catalog/history are bounded to 200 list entries, 100 versions and 200 visible binding rows per
detail. Unlimited pagination, global Settings unsaved-close protection, full axe/WCAG/screen-reader,
foreground FPS and physical touch tests are not claimed. Production email ownership verification,
deployment operations and signing remain the limitations recorded in A1. The review EXE is unsigned.
Referenced Skill availability is checked again on writes; live dependency-availability projection
and adoption into local Run snapshots belong to the remaining execution resolver work.
User aesthetic acceptance remains pending screenshot review; no production service was deployed.
