# 个人工作台与组织知识协作分阶段实施方案

日期：2026-11-06（America/Los_Angeles）。代码基线：`0a7f7f28e4fba62a6b909a88f59ccd03e186f5aa`。

目标是免登录使用本地个人多 Agent 工作台，登录后可进入组织空间，利用经过授权的技术与业务资料分析需求，复用现有执行引擎完成开发，审核后将成果沉淀为组织知识。组织负责人可以按成员分配需求；组织角色不替代项目权限或成员本机执行授权。个人空间、项目及本地知识始终保留，不因登录自动上传。

## 实施顺序与验收

| 阶段 | 实现内容 | 验收条件 | 状态 |
| --- | --- | --- | --- |
| K1 组织知识底座 | 技术／业务资料，草稿、不可变版本、发布／废弃／撤销，组织／项目权限，发布知识检索，桌面具名接口 | 真实 PostgreSQL 与 HTTP 测试；跨组织／项目隔离；并发编辑冲突；旧迁移不变；桌面凭据不外泄；个人回归 | 已完成服务与桌面接口，验收见 K1 报告；无新增界面 |

| K3 知识回写 | 从已验收产物生成知识候选；人工审核、去重、新版本发布；关联需求、Run、产物和验收证据 | 未验收成果不能自动发布；拒绝保留；并发版本冲突可见；新需求能再次检索获批知识 | 已完成本阶段：独立本地验收、人工确认分享、项目私有候选与人工审核；693 测试通过／4 跳过，187 桌面检查、四条原有回归与 EXE 验证通过；见 K3 报告及诊断／范围说明 |

每阶段先更新 ADR／契约，再实现与验证；证据随实现保存。只有满足相应验收条件才能改为完成，后续阶段不从接口名称或页面原型推断完成。

## 各阶段开发任务

### K1 知识资产基础

组织服务新增独立知识文档与版本表，复用既有成员／项目权限及审计事务。资料分类为技术和业务，内容包含标题、正文、标签；每个版本具有明确发布状态及内容校验值。新增知识列表、详情、新建、创建版本、编辑草稿、状态转换、检索七个桌面接口。测试同时覆盖正常读写与越权、并发、撤销和恢复。

### K2 知识管理与开工分析

1. 在现有组织设置中增加知识管理和检索入口，沿用已批准的组件、令牌与动效。实际读取 UI 契约并加载可用的必需设计技能，记录不可用来源；完成浅深色、窄窗口、缩放和可访问性验收。
2. 需求创建／开工前，以需求描述检索有权限的组织业务规则、术语、技术规范和历史决策。展示命中资料、来源版本和未覆盖的问题，允许负责人补充材料或调整选择。
3. 将所选资料作为不可信参考数据传入现有需求分析和技术设计阶段。产出业务目标、范围／非目标、约束、待确认问题、验收标准、技术方案及流程草案；资料不足时明确请求人工补充，不虚构组织规定。
4. 保存独立的需求知识引用快照，包含组织／项目、文档／版本／校验值、选取理由和访问主体。资料更新不会改写已执行上下文；权限撤销后拒绝新读取，审计引用仍保留。个人模式只使用本地资料源，不调用组织接口。
5. 流程草案经用户批准后才产生真实任务与依赖，复用现有事务、DAG 校验、门禁、Agent 分配和 Worktree。知识不得授予工具权限或覆盖组织强制门禁。

### K3 开发后的知识沉淀

1. 从已验收需求提取业务规则变化、技术决策、接口变化、问题解决方法和复用经验，关联当前验收证据、交付物、Run 及提交。
2. 建立组织知识候选状态：待审核、退回、已发布。候选不是已发布事实；普通成员可提交候选，指定知识审核人决定是否发布或生成已有知识的新版本。
3. 根据既有版本、相似标题和关联需求提示重复／冲突，由审核人选择合并更新或新建；发布使用期望版本和幂等请求，未知写入结果先核对，不盲目重放。
4. 需求完成与知识发布分别显示。拒绝发布不伪造需求失败；组织策略可要求知识审核门禁。再次开工的需求必须能检索到获批版本，形成可验证的复用链。

### K4 按成员派发与执行

1. 增加服务端权威的成员工作分配，包含组织／项目、需求、分配人、负责人、验收标准、优先级、截止时间、版本及状态。派发采用明确项目权限，leader 映射到权限配置，不依据职务文字自动授权。
2. 成员桌面收件箱支持查看、接收、拒绝及原因；负责人可跟踪进度、取消或重新分配。接收／取消／重分配使用版本条件和幂等键；同一分配不能生成重复本地需求。
3. 接收后显式关联该成员的本地项目及需求 Worktree，复用原有需求多 Agent 流程。设备授权、文件修改、测试进程、Git 合入与发布保持独立审批，组织负责人不能凭派发权操作成员任意目录或 Shell。
4. 服务端保存共享状态及证据引用，本机保留执行事实；映射中不上传绝对路径和密钥。成员断网、降权、退出或设备撤销后停止新的组织副作用；不确定结果进入人工核对。

### K5 完整链路验收

使用两个真实账号和两台独立桌面接入同一组织服务，依次完成 leader 派发、成员接收、资料辅助分析、批准流程、多 Agent 开发、真实测试与审查、需求验收、知识审核发布，以及下一需求引用该知识。另覆盖撤权、重复接收、跨项目访问、断网、服务／桌面重启、未知副作用对账、个人空间保留和安装包版本一致性。共享服务的 TLS、数据库备份与显式升级在部署环境验收，未经实际验证不标为上线。

## 数据与执行边界

- 组织服务及 PostgreSQL 管理组织知识、版本和发布状态；本机 Runtime／SQLite 继续管理本机项目与执行事实。
- Main 持有登录凭据，通过有界 HTTP 与具名 preload 方法访问组织服务；Renderer 不直连数据库、HTTP 或文件系统。
- 知识正文是参考数据，不能覆盖执行策略；知识内容不授予文件、命令、Git 或发布权限。
- K1 接受有界文本／Markdown 和标签，不引入文件上传、网页抓取、向量服务、外部连接器、自动模型分析或知识缓存。
- K2 之前不会把“可检索接口”宣传为已经用于 Agent 分析；K3 之前不会把知识更新文档宣传为已发布到组织。
- K4 使用项目级派发权限，职务名 leader 仅用于显示。按人派发与向授权设备提交单个远程 Job 分别记录，复用同一执行内核。
