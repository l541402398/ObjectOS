# ADR-0070 — Apply the user-approved DAG aesthetic across the real product

- Date: 2026-10-29 (America/Los_Angeles).
- Status: explicitly authorized by the user's attached screenshot and request in this conversation.
- Visual authority: `docs/next-ui/visual-regression/APPROVED-design-lab-dag.png`, reaffirmed by the
  user's 2026-10-29 screenshot. The user approves the composition/material and requests real menu
  mapping and system-wide adoption. This is approval to implement the rollout, not a claim that
  subsequent screenshots have already been accepted.

## Decision

1. Finish and isolate the existing A2.2a device/consent checkpoint. It does not enable remote
   execution. Leases, Run configuration adoption and execution checks remain the next A2 slice.
2. Then prioritize the system-wide Premium Liquid Glass implementation. Use the actual page
   registry and existing named actions for navigation; prototype rail actions must not masquerade
   as real routes. Keep Settings global, preserve every reachable product feature, and keep the
   Agent drawing/connection workspace. Do not recreate its removed chat inner page.
3. First resolve the frozen contract's five Lab prerequisites with current evidence: durable
   authority; icon-only stage anchors/tooltips; readable type/contrast; solid focused DAG edges;
   task-inspector hierarchy/accessibility. Preserve the approved DAG composition and prototype
   designation. Changes to prerequisites carry before/after screenshots and an explicit rationale.
4. Share semantic tokens, optical frame/ambient material, focused reading surfaces, navigation,
   controls, overlays and interruptible Motion. Light/dark, narrow windows, keyboard and 125%
   zoom are part of the work. No new shader or displacement filter is enabled without measured
   compatibility/performance evidence. Keep the known safe static glass fallback.
5. Audit every registered product route and Settings section, with representative interactions,
   screenshots and real checks. A global CSS import is not evidence that every screen is polished.
   Report any gaps individually; do not call migration or visual acceptance complete prematurely.
6. During this UI rollout, do not modify Runtime, model/tool policy, scheduling, persistence or
   server behaviour. Scope changes are presentation and renderer navigation, with existing APIs.

## Evidence

Keep A2.2a authority evidence under `docs/org-upgrade/evidence/A2.2a/`. Keep the system visual
inventory, comparison captures, source/OSS provenance, checks and remaining issues under
`docs/design/system-premium/`. Include evidence in the same implementation commit and push the
review branch. Do not auto-merge or publish a production build.
