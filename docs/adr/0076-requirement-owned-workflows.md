# ADR-0076: Requirement-owned workflows, inherited by every task

Status: Accepted for implementation, 2026-10-30. Supersedes the transitional UC
compatibility product direction in ADR-0075 after the user's explicit clarification.

## Product contract

- The business hierarchy is requirement → development tasks → workflow steps / Agents.
  UC is removed from product concepts, authoring APIs and task execution prerequisites.
  Migrate existing group descriptions into ordinary requirement materials, preserve
  historical runs/reviews, and remove the obsolete live grouping structure safely.
- At requirement creation select an existing workflow template or create one with
  drag/drop. Ship requirement analysis, requirement review, technical design, design
  review, development and testing nodes; optional code review / knowledge nodes may
  be composed from the same supported stage registry.
- Every task, including tasks generated by AI, inherits that requirement's frozen
  workflow definition. Task dependencies and workflow edges are separate persisted
  DAGs. Neither canvas positions nor chat messages drive execution.
- Node assignments are explicit. In manual/assisted use the user selects Agents;
  autonomous assignment uses the existing active model connection and records its
  validated choices. A rule-based fallback must never be called AI assignment.
- A template edit creates a new immutable version. Binding changes before execution
  update unstarted tasks atomically; started requirements keep their selected version.
- Users work from the requirement: choose workflow, confirm tasks/owners, start,
  inspect results. Existing operational detail pages and deep links remain reachable.
  Tool approvals are handled in context with exact scope and deliberate confirmation.

## Runtime and evidence

- Reuse the Node Runtime, native AgentRunner, existing provider configuration, task
  leases, Run / ToolCall / Artifact records and existing coordination entry point.
  Add workflow orchestration as persisted business state, not another Agent engine.
- A user starts a task flow once. Assigned steps can continue at known completion
  boundaries; pause holds subsequent steps. Unknown/interrupted effects require
  reconciliation and are never replayed automatically.
- Bind each node execution to a real Run and immutable input document versions.
  All tasks must pass their configured nodes before task acceptance can finish.
  A Run reporting completion alone is insufficient: document nodes need persisted
  materials, reviews need a verdict tied to current input versions, and testing needs
  a successful real command with unchanged tested source content.
- Reuse Artifact body storage and real create_artifact ToolCall results for document
  output. Runtime-owned provenance links prevent a renderer-authored metadata claim
  from satisfying a flow step. Rejected/stale reviews and missing outputs stay visible.
- Plan approval, document review, task acceptance, Git integration and tool permission
  remain separate facts. Workflow customization cannot grant file, command, Git or
  deployment authority or bypass existing high-risk acceptance policy.
- Surface documents in the requirement's workflow journey and the Agent collaboration
  inspector, with the producing task, Agent, run, version and actual body available.

## Migration and validation

Append migrations; never alter released V1–V39. V40 is the tested transitional nullable
UC linkage. V41 introduces workflow versions, requirement bindings, task step state and
output provenance. V42 archives legacy group material with task links and retires the
live grouping columns and table without rewriting historical run or approval JSON. Existing data
must remain readable; pending requests whose frozen scope changed must be rejected.

Test template validation/versioning, inheritance through both manual and AI task
creation, assignment authorization, real node runs/outputs, rejected and stale reviews,
test evidence, pause/restart/unknown outcomes, completed-task gates and legacy migration.
Inspect the actual desktop in light/dark at 1440×900, 1280×800 and 1024×768, including
drag/drop, keyboard alternatives, focus, empty/loading/errors and reduced motion.

Evidence: docs/v2/evidence/requirement-guided-flow/. A3.2a prior evidence is frozen
in docs/v2/evidence/requirement-integration/ and must not be overwritten.
