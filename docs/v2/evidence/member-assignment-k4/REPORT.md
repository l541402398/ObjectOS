## 实现与入口

- 设置 → 账号与组织 → 需求分配。项目所有者／维护者选择当前项目成员，派发需求目标、验收条件、
  优先级及可选截止时间。组织管理员没有项目权限时不能派发；职务名称不授予权限。
- 成员在同一入口查看自己的分配，接收或填写原因拒绝。接收须选择已有本机项目并确认，服务器回执
  核对成功后才事务创建一个普通需求、默认手动流程及不可变来源。此操作不调用模型或创建 Git 工作区。
- “打开本机需求”进入现有需求工作台。“组织资料”标签显示分配状态，可固定选择所属项目的业务／技术
  资料、显式更新进度、提交交付。沿用现有 Native 多 Agent 流程；工作区、文件、测试及 Git 仍独立审批。
- 进度取自 Runtime 中的真实任务／运行计数。交付须有当前 K3 人工整体验收，分享最多八个产物引用及
  合入提交标识。组织负责人对当前报告与版本另行确认交付或退回补充；任务／Run 结束不自动完成分配。
- 负责人可撤销或改派。改派在服务端事务内关闭旧标识，创建新负责人待接收的新标识，保留原成员本机
  成果及历史。旧分配不会重新绑定给另一个成员；完成分配不能原地改派。
- HTTP 前持久化固定内容、账号／组织、操作标识及本次人工确认。未知结果先 GET 核对，不自动重发。
  显式重试仍使用原标识／内容；人工关闭本机待办不代表服务器成功或撤销，之后仍可 GET 核对。
- 新增具名、有界的 Main↔Runtime 授权通道，在模型、工具及批准后的工作区／测试／Git 操作前重新检查
  当前身份、项目权限、接收来源及状态。退出、离线、撤权、撤销、改派后停止新的分配工作。个人需求
  不触发这个组织授权通道。待复核／已完成分配停止开发，但可独立提交已验收知识候选供 K3 审核。
- 旧版计划讨论不带需求任务来源，因此分配需求明确禁用该入口，继续使用按需求的 Native 流程。
  新增回归确认不会写入讨论消息或调用模型；个人计划讨论仍实际完成。外部 CLI 同样不支持分配需求。

服务端追加 PostgreSQL 迁移 7，本机追加 SQLite 迁移 47；不改写旧迁移。按人分配独立于执行端 Worker Job，
使用现有 Runner。接收来源是应用内幂等标识，不是密码学设备认证或远程执行授权。交付证据标记为
`desktop-owner-attested`，不宣称服务器验证了本机代码。结构化内容不上传根目录、密钥或模型对话；
自然语言说明／产物标题仍需用户检查。无本机项目的负责人操作保存控制面确认记录及服务器审计，
不会为审计虚造一个本机项目；本机接收、进度和交付还保存批准的 Run／ToolCall。

决策：[ADR-0087](../../../adr/0087-member-requirement-assignment.md)。
