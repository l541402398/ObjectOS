# ProjectOS V1.6 — 给开发 AI 的执行提示词及验收清单

## 使用方式

把整个解压目录放在代码库 `docs/design/v1.6/`，将本文件内容发给 Codex、Claude Code 或其他 AI 开发工具。该目录下 53 张 PNG 是独立页面规格，不能仅凭总览图开发。

## 可复制的主执行指令

你正在真实 ProjectOS Electron 代码库中实施 V1.6。先阅读 `04_功能设计与优化文档/01_V1.6完整实施说明书.md`、`02_功能需求PRD.md`、`03_UI_UX优化规范.md` 和 `06_设计索引与验收清单/design_index.csv`。遍历 12 张已确认原图与 41 张新增独立设计图，并检查 `05_视觉资产与现状审计/当前系统UI审计.md` 及原始截图压缩包。

**开始前必须扫描现有真实项目。** 列出各页面组件路径、React/Ant Design 主题 Token、SQLite 和 IPC、V1.3 DAG、V1.4 自主运营、V1.5 Agent/Skills/Runtime/ACP/Harness 扫描的已经完成程度；输出差距矩阵和迁移风险。不要推倒重做或创建没有业务连接的 UI。

**严格按图实现。** 12 张已确认设计稿为视觉母版，41 张新增独立稿须对齐母版并等待用户进一步确认。延续蓝紫光学玻璃、山峦环境光、卡片材质分层、右侧 Inspector、简洁 UI 文案。不可用一张设计图铺满整个页面，也不可用静态假数据冒充已连接、已安装、已运行、已授权。

**保证业务链路。** Agent Studio 创建/编辑/复制自定义 Agent，Persona/Skills/Runtime 可独立配置；工作流节点通过 agentId 真正调度自定义 Agent 并回传日志与产物；现有本地 Harness 扫描动态接入 Runtime Registry；OpenSpec 作为可选工作流；AI 连接普通用户只需要 Provider、必要 Endpoint、Key、测试和模型选择；危险工具执行有策略审批。

**修复既有缺陷。** 左侧导航展开/折叠期间不允许文字变竖排、布局跳动或快速切换卡在半程。正文清晰，默认 ≥14px，次要文字原则 ≥13px，AA 对比度，深浅色主题与 Windows 100/125/150% DPI 验收。移除解释性、营销性、重复占位文案。

**执行顺序**：现状审计 → 设计 Token 和公共组件 → 全局导航/设置 Shell → 逐页视觉实现 → 真实 IPC/数据库/Runtime 联调 → Electron 逐页截图和录屏对照 → 用户确认差异 → E2E/打包测试。每完成一页都要提供实际截图、相应参考图、差异表、测试结果和未完成项；不要在只完成 CSS 后宣称完成。

## P0 验收检查

- [ ] 53 个独立设计文件均能从索引准确定位；12 个批准稿不被旧草稿替换。
- [ ] 项目中心、项目详情、Agent 工作台、任务、知识库、资源、工作流、审计、设置均可从实际导航访问。
- [ ] Agent Studio 的 Persona、Skills、Runtime、预览和保存使用真实业务。
- [ ] 本地 Harness 扫描的状态、版本、认证和能力与真实环境一致。
- [ ] 旧 V1.3 DAG 和 V1.4 任务无回归，自定义 Agent 能执行并回传。
- [ ] AI 连接无需温度/协议即可按服务商完成普通配置与真实模型使用。
- [ ] OpenSpec 不被错误归类为 Runtime，不启用时不阻碍普通任务。
- [ ] 高危工具与 Git 变更有后端权限校验与审批。
- [ ] 侧栏动画全程无竖排中间态，快速连续点击仍到达稳定终态。
- [ ] 深浅主题、不同缩放/DPI、键盘导航、减少动效与性能降级通过。
- [ ] 不含虚假服务商状态、虚构模型能力、虚假已安装 Runtime 或硬编码成功值。
- [ ] 开发 AI 提交真实 Electron 截图、录屏和功能测试报告。
