# ProjectOS V1.6 UI/UX 优化与高保真还原规范

## 1. 视觉母版与设计优先级

ProjectOS V1.6 采用「Prismatic Glass / 光学玻璃工作台」：蓝紫环境光、山峦/星空背景、低饱和深色基底、玻璃分层、局部青绿或橙色语义高光。12 张逐页确认的原图是视觉母版；新增 41 张完整静态页面需与此母版对齐。不能因为实现方便，把高保真设计降级成普通灰色卡片后台。

设计图中的统计数字、人名、模型列表、权限状态均为示例，真实应用只展示业务数据。保留专业的信息密度，但删掉欢迎词、产品广告、大段解释性文字和重复说明。

## 2. 玻璃材质分层规范

| 层级 | 用途 | 材质要求 | 避免 |
|---|---|---|---|
| G0 环境层 | 山峦、空间、渐变背景 | 静态图层 + 节制氛围光 | 高动态背景影响文字 |
| G1 导航玻璃 | 左侧栏、顶栏、浮动导航 | 背景模糊、半透明、边缘描边 | 纯黑/纯灰平板 |
| G2 内容玻璃 | 卡片、指标、状态列表 | 色彩克制、光影有层级，文本容器高不透明 | blur 施加到文字父节点 |
| G3 操作玻璃 | Modal、Dropdown、Inspector | 明确前后景分层、投影、软边高光 | 过度磨砂导致对比度不足 |
| G4 交互态 | hover、focus、selection、loading | 连贯 120–250ms 的渐变过渡（可调整） | 强发光/无意义动效 |

`backdrop-filter: blur()` **只是背景模糊，不是物理折射**。需要光线扭曲时，应实现可降级的 GPU/Shader 局部折射或仅采用视觉暗示，不得以 blur 冒充。GPU 不可用、低功耗与 reduced-motion 模式需关闭昂贵特效。

## 3. 导航折叠修复 P0

已发现侧栏展开/折叠时的中间态文字被挤成竖排、图标/文字错位及主体跳动。应保持图标容器宽度恒定；文字用 nowrap / overflow clip 且在合适阶段渐隐或延迟显示；整栏使用单一受控宽度状态、CSS transition；不要让自然文档流中间态自动逐字换行。连续快速点击要打断旧动画并得到确定终态。监测 100%、125%、150% DPI 及 1024×768 窗口。

## 4. 全局信息架构

主导航：项目中心、Agent 工作台、工作流、任务、知识库、资源、运行审计。设置中心：AI 连接、模型目录、Agent 路由、Runtime 管理、工具与插件、外部 Agent、团队与权限、系统设置。设置应有清晰的分类与短标签，减少长滚动表单。选择框不应被无意义帮助文案包围。

宽屏以主区 + Inspector 的二/三栏布局为主。较窄窗口优先折叠 Inspector 或模板栏，保留任务主内容；禁止通过 transform: scale(0.8) 整体缩小整个 App。弹窗底部操作栏固定，输入焦点仍可滚动可见。

## 5. 组件与交互一致性

- Nav：收起与展开后图标、分组及焦点位置稳定。
- Card：不同用途的统计卡、Agent 卡、任务卡材质分级，同级卡组件复用。
- Form：每个字段有清晰标签，必要校验就近提示，避免重复 Placeholder。
- Tabs：状态保留，跨 Tab 不丢未提交草稿，必要时提供脏表单确认。
- Inspector：右侧详情支持固定宽度、独立滚动和收起；详情不能遮住主要内容。
- Graph：保持 V1.3 的多 Agent 层级 DAG 与右侧 Inspector，不得改为普通列表或简单线性图。
- Empty/Error：显示真实空状态、失败原因和有效操作，无“已完成”装饰徽章。
- Modal：主操作可见、危险操作有确认、Esc/焦点陷阱有效。

## 6. 字体、色彩与可访问性

正文默认 ≥14px；辅助正文原则 ≥13px；标签、表头可以结合字重、行高调整，但不得用过低对比度制造“科技感”。普通文字对比度 ≥4.5:1，大字号 ≥3:1；图标无法替代操作名称。避免半透明父容器导致文本一起发灰、Electron DPI 下字形发虚。支持深浅色主题，而非把亮度直接取反。

## 7. 核心场景的专属 UX

**AI 连接**：普通流程只有服务商、地址与 Key、测试和模型选择；协议温度隐藏高级设置；服务商状态与模型发现同步真实结果。

**Agent Studio**：左模板、中分段配置、右实时预览；Persona 与 Skills 分区，Runtime 动态发现；右侧摘要不能编造值。

**Runtime 管理**：突出真正的 Harness（OpenCode/Claude Code/Codex 等实际扫描到的工具）；Shell、Browser、Tool 等分类准确，不与 Runtime 混列。

**DAG 工作流**：保持你已确认的节点库、中央画布、层级依赖、右 Inspector 和底部日志的独立高清原稿。

**运行审计**：任务运行状态、Token 和费用都需要真实回传；没 usage 时显示“未知”，不能显示零来误导。

## 8. 高保真实施与验收流程

1. 依据 `design_index.csv` 找到页面、设计状态与完整高清图。
2. 对现有代码做页面/功能对照，列出必须保留的入口与真实数据 API。
3. 用统一 Token 与 React/Ant Design 复刻布局、组件、玻璃层次和交互。
4. 实机启动 Electron，按一致窗口大小截全屏；同步录制导航、悬浮、弹窗、提交过程。
5. 检查骨架比例、间距、字重、边界、材质、背景亮度、层级与滚动行为。
6. 修复差异后再测试深浅色、DPI、窗口缩放、键盘、真实性及业务回归。
7. 提交截图对照表、测试记录、无法实现的原因与代替方案。

**视觉批准等级**：已确认 12 张为固定母版，新绘制 41 张标记“待复核”；不可把本轮生成的 HTML 静态稿视作生产级最终实现。
