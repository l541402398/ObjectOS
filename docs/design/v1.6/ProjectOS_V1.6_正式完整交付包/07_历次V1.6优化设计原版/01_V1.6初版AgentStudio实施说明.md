# ProjectOS V1.6 — Agent Studio 可视化配置工作台实施设计说明书

> 版本：V1.6｜性质：独立版本、增量开发｜适用：Electron + React + TypeScript + Ant Design + SQLite + IPC｜实施对象：Codex / Claude Code / 其他 AI 编程 Agent

## 0. 版本定位与强制约束

V1.5 解决“Agent 的名称、人设、Skills 与开放式 Runtime 如何定义并真正执行”；V1.6 解决“这些能力如何以专业、直观、精致且可访问的桌面交互呈现”。

本期必须保留 V1.3 层级式 Agent 工作流图、V1.4 自主运营/自动修复与 UI 可读性整改、V1.5 AgentDefinition/Persona/Skills/Runtime Adapter/ACP 等已有真实能力。禁止推倒重做、重复创建数据源或用静态假数据代替实际接口。**参考图是视觉验收基准，不是灵感图。**

交付必须覆盖：Agent 模板库、创建/编辑/复制/管理、五阶段配置、右侧实时预览、真实 Runtime 诊断、Skills 兼容性、配置保存与版本、响应式和深浅色主题。

## 1. 设计输入与现状审计（M1.6-00）

输入：现有 Agent 管理弹窗截图（单栏普通表单）与本包附带的 Agent_Studio_Visual_Reference.png（三栏参考图）。审计已有组件、路由、状态管理、SQLite 表、IPC 事件、RuntimeProfile、Skills 注册中心、AgentRun 和主题 Token。

在写代码前提交《现状与差距表》，逐项列出：功能是否已存在、实现文件、真实数据接口、拟复用组件、缺失能力、迁移风险、验收方式。无法确认的功能必须标记“待核实”，不得当成已实现。

## 2. 信息架构与页面模式

Agent Studio 为统一管理入口：左侧 Agent 列表/模板导航，中间配置工作区，右侧实时预览/诊断摘要；创建、编辑、复制共用一个表单内核。列表模式保留搜索、筛选、状态、编辑、复制、归档入口；创建模式可从模板或空白开始。不得因 UI 改造丢失现有 Agent 管理功能。

顶部五个配置 Tab：**基础信息 / 人设与提示词 / 技能 / 运行环境 / 高级设置**。允许用户直接切换 Tab，草稿不得丢失。底部固定操作栏根据模式显示“取消 / 下一步 / 上一步 / 创建 Agent / 保存修改”。

## 3. 视觉布局与尺寸（M1.6-01）

- 桌面宽屏三栏：左 20%–23%，中 50%–55%，右 24%–28%；具体以设计参考图与真实窗口为准。
- 弹窗宽度 min(1480px, 92vw)，高度 min(900px, 90vh)，圆角 20–24px；视口小于参考图时优先保证中间表单可用。
- 左侧模板区独立滚动；中间表单内容独立滚动；右侧预览可独立滚动；底部操作栏固定，禁止遮挡输入框。
- 背景仅适度遮罩与毛玻璃；高密度文字、表单和预览信息面板采用高不透明度背景。
- 不通过 transform: scale 或全局 zoom 压缩整个页面；避免父容器 opacity/filter 导致字体发虚。
- 细腻边框、柔和阴影、统一间距与图标；蓝色强调色沿用 ProjectOS 现有主题 Token，禁止另建一套视觉语言。
- 设计参考图中的占位数据不是实际默认值，生产环境只能显示真实配置或“未配置”。

## 4. 左栏：模板与 Agent 导航（M1.6-02）

模板搜索、推荐模板、从空白创建；模板包括通用助理、后端、前端、架构师、测试、运维、产品经理、UI 设计、数据分析等。模板为可编辑的配置预设，不是锁定角色；模板可关联 Persona、推荐 Skills、默认权限建议，但**不能自动授予危险权限**，也不能将 Runtime 标记为已安装。

每行使用统一图标容器、名称、明确选中态、键盘焦点态。若存在已创建 Agent，列表模式应展示真实 Agent，并支持搜索、状态筛选、编辑/复制/归档。模板与已有 Agent 列表须明确区分，避免误操作。

## 5. 中栏：基础信息 Tab（M1.6-03）

字段：头像（预设/颜色/已有资源）、名称（必填）、角色（必填，可自定义）、空间、可见性、简介、分类、标签。布局按参考图：头像与名称/角色形成紧凑分组；空间/可见性双列；简介多行；分类使用胶囊式选择；标签为可移除 Chip。

字段绑定单一 AgentDraft 状态；输入即时校验，避免大段帮助文案。角色与简介不得与 Persona 高级配置重复存储出冲突；可使用角色简称与详细人设的清晰映射。

## 6. 中栏：人设与提示词 Tab（M1.6-04）

结构化人设字段：角色定位、专业背景、核心职责、工作原则、沟通风格、行为限制。提供高级 System Prompt 编辑器、来源分段预览、冲突提示。采用分组卡片、分栏与折叠高级区域，禁止将全部内容做成无层级的 TextArea 长列表。

与 V1.5 PersonaCompiler 对接：保存时记录配置版本；执行时加载固定快照。必须验证结构化字段及自定义 Prompt 在真实 AgentRun 中生效。外部 Runtime 不支持某种注入时准确显示限制，不得假称成功。

## 7. 中栏：Skills Tab（M1.6-05）

Skills 以搜索 + 筛选 + 卡片列表呈现：名称、简短用途、版本、来源、启用状态、Runtime 兼容性、所需工具权限。支持添加/移除、启停、从本地导入符合既有规范的 SKILL.md 包；支持查看 Skill 详情和依赖，但默认界面不堆说明文字。

严格区分 Skills（流程与指导）、Tools（执行能力）、MCP（工具服务）。勾选 Skill 不等于授权 Shell/文件/网络权限；兼容状态必须由 V1.5 capability/Policy 服务实时计算，失败原因可查看。

## 8. 中栏：运行环境 Tab（M1.6-06）

采用 Runtime 可搜索卡片选择器，**不允许硬编码为有限几个名字的白名单**。来源：V1.5 的已安装 Adapter、ACP 兼容发现、用户注册的自定义 Runtime。可展示 OpenCode、DeepSeek Harness、Qwen Code、Claude Code、Codex、Gemini CLI 等实际检测到的候选，但显示与否以真实 Registry/Adapter/本机状态为准。

卡片字段：Runtime 名称/图标、协议类型、安装状态、版本、认证状态、Capabilities、模型/Provider、诊断按钮。选择后显示实例配置（本地二进制/服务地址、模型、超时、并发、环境变量引用等）；敏感值不得回显明文。

Runtime ≠ Model Provider：Qwen Code 与 Qwen 模型、DeepSeek Harness 与 DeepSeek 模型必须明确区分。自定义 Runtime 配置要走 V1.5 统一 Adapter/ACP 契约，UI 不得自建私有执行路径。切换 Runtime 时保留草稿但重新评估 Skills、工具权限和模型兼容性。

## 9. 中栏：高级设置 Tab（M1.6-07）

工作目录、共享目录或 Git Worktree、工具授权、审批策略、超时、并发、预算、备用 Runtime。危险操作须显式审批；展示最小必要权限摘要。备用 Runtime 切换只在可安全重试边界进行，禁止未经授权转移未提交的工作区变更。

## 10. 右栏：实时 Agent 预览（M1.6-08）

显示头像、名称、角色、简介、标签、所属空间、可见性、Skills 摘要、Runtime/模型与真实连接状态。右侧数据从**同一 AgentDraft** 派生，不单独维护可能过期的副本。空字段显示“未配置”，不能填充虚构技能、假成功状态或营销示例。

参考图的“使用示例”区改为可选的“任务示例”或“能力预览”，仅在模板确实提供示例时显示；普通空白 Agent 默认隐藏。右栏支持收起、独立滚动和键盘导航。

## 11. 状态模型、组件拆分与数据流

建议组件：AgentStudioShell、AgentTemplateSidebar、AgentEditorTabs、BasicInfoForm、PersonaEditor、SkillsPicker、RuntimePicker、AdvancedSettings、AgentLivePreview、AgentStudioFooter、RuntimeDiagnostics。

建议状态：AgentDraft（单一真源）、dirty、validationErrors、activeTab、templateId、runtimeCapabilityResult、saving、mode。表单切换不丢草稿；关闭有未保存修改时确认；重复提交保护；异步检测结果必须防止过期响应覆盖新选择。

数据流：现有 IPC → 领域服务 → AgentDraft 初始化 → 表单编辑 → schema 校验 → agent.create/update → SQLite 版本记录 → 刷新真实 Agent 列表/预览；Runtime/Skills 诊断单独异步读取，不得伪造。

## 12. UI 文案与字体清晰度 P0 规范

- **移除解释性文案**：不添加欢迎词、营销口号、功能宣传段落、重复解释字段的描述、冗长 placeholder。
- 仅保留必要标签、按钮、状态、校验错误、兼容性限制、危险权限说明。
- 正文默认 ≥14px，次要文字原则上 ≥13px；中文字体采用可靠系统回退，避免大面积 300 字重。
- 普通文字与背景对比度 ≥4.5:1，大字号标题 ≥3:1；禁用状态可按相应可访问性规范处理。
- 深浅主题分别验收；Electron 在 Windows 100%、125%、150% DPI 下检查清晰度和布局。
- 玻璃效果只用于侧栏、工具条、浮层等低密度区域；日志、表单、预览详细信息用清晰不透明背景。
- 图标不能代替必要文字标签；交互状态不能只依赖颜色。

## 13. 响应式与可访问性

≥1280px 三栏；约 960–1279px 左侧可收窄，右侧可折叠；更窄时模板以抽屉显示，预览以 Tab/抽屉显示，中间表单保持完整宽度。以上断点可按现有 Electron 最小窗口尺寸调整，必须实际测量。

Tab 可用键盘操作；表单有可访问名称、错误关联、焦点可见；弹窗焦点陷阱、Esc 关闭规则和未保存确认正确；动效尊重 prefers-reduced-motion；禁止横向溢出与底部按钮遮挡。

## 14. 安全、兼容与回归

Renderer 不直接访问 SQLite、文件系统、密钥和子进程。所有写入通过既有 IPC 校验与授权。模板导入不得执行脚本或自动授予权限；配置导出移除 API Key、Token、敏感环境变量与不必要的机器路径。

兼容现有 V1.3 Agent 工作流图的 agentId/runId、V1.4 调度与审批、V1.5 Agent 配置版本/Runtime Adapter。旧 Agent 可正确回填编辑，新字段有安全默认值，数据库迁移可回滚。

T01 创建 Agent，名称/角色/头像/空间/分类/标签真实保存，重启后可恢复。

T03 五个 Tab 往返切换不丢数据；关闭脏草稿有确认。
T04 编辑已有 Agent 时全部配置准确回填；复制后产生新 ID。

T13 Windows 100/125/150% DPI、浅色/深色主题下无模糊灰字、裁切或横向溢出。
T14 键盘 Tab、焦点、Esc、错误提示和减少动效模式可用。

## 19. 完成定义（Definition of Done）

用户能够在高保真 Agent Studio 中选择模板或空白创建 Agent，独立配置名称、人设、Skills、开放式 Runtime 与权限，实时预览并保存；编辑/复制/归档功能真实可用；现有 V1.3–V1.5 功能不回退；深浅色和 DPI 测试合格；没有冗余解释性文案；视觉效果经过实际 Electron 截图比对验证。
