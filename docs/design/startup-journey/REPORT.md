# 启动动画与目标旅程修正

日期：2026-10-30。基于 `710f83a0580c68842309aabd97dc1851db168918`，分支 `codex/premium-system`。
本次范围是用户连续提出的两项反馈，延续已批准的 Premium Liquid Glass DAG 风格。
前一轮完整系统迁移的证据保留在 `../system-premium/`，不覆盖旧验收记录。

## 实现

1. 启动恢复完整品牌、双轨加载动画与玻璃光学背景。初始 HTML、路由等待和 Bootstrap 等待复用
   `boot-content.html`，配色与材质来自统一令牌。HTML 载入前读取已保存的主题、减少动效和透明度
   设置，避免先出现深色占位。无最低展示时间、虚构百分比或启动阶段计数。
2. 保留本地字体就绪后再挂载产品的机制，字体声明归并至早期样式，等待字体集合就绪。
   启动失败仍显示实际错误和重试入口，渲染异常复用同一主题外壳。
3. 旅程默认显示项目准备、需求、计划、审核、授权、执行、验证、审查、交付。
   当前阶段有名称、状态、高亮和 `aria-current`；完成阶段有勾选，未完成阶段有序号。
   完成数量只在详情中显示“已完成 x / 9 阶段”，避免被误解成阶段位置。
4. 阶段入口、下一步及重新验证沿用真实 API 投影与原有操作。详情支持键盘展开、Escape 关闭及
   焦点返回，点击外部关闭。窄屏节点与名称上下排列，全部阶段名称仍可见。

未改变 Runtime、IPC、数据库、策略、审批或自主/辅助/托管模式。构建配置只插入本地静态 HTML；
没有动态 HTML 注入、Renderer 文件访问、CSP 放宽或新增网络监听。

## 设计来源与取舍

- 复查批准 DAG 截图、统一令牌、UI 合约、弹层规则及恢复文档；设计优先级不变。
- UI UX Pro Max 实际查询保存在 `sources/`：采用本地 Noto Sans SC、明确当前位置、键盘焦点、
  减少动效。首次通用 CJK 查询返回非中文字体，改为 Chinese Noto sans 后匹配；不采纳通用
  Productivity Tool 的青绿/橙色调，也不引入远程字体。
- 实读 Vercel composition 的 children 组合规则、React 的并行等待与无闪烁偏好初始化规则。
  为满足生产 CSP，把示例中的内联初始化改成外部本地脚本。
- 实读 Impeccable 的 craft-floor、animate、audit；使用实际现有上下文，不创建虚构 PRODUCT.md。
  源码检测见 `validation/source-detector.json`，不能替代原生像素和主观设计审核。
- Motion 实际安装入口为 `apps/desktop/node_modules/motion/dist/es/react.mjs`；用于详情位移过渡。
  React 尚未加载时的启动动画使用 CSS，系统和应用减少动效均生效。
- Sim、Liquid Glass、React Bits Aurora 沿用上一轮实际源码与兼容性记录；本次不更改画布构图，
  不重新引入已测得低帧率的 shader。专用 skill 加载接口不可用，已实际读取本地 SKILL 文件。

## 验证方法和首轮修正

`scripts/startup-journey-e2e.mjs` 在隔离的真实持久化示例中测试，不改用户数据。
1440/1024 × 亮/暗 × 100%/125% 使用原生窗口尺寸、原生缩放和 `capturePage()` 截图。
只在测试环境暂缓字体等待 Promise，以观察短暂启动画面；实际字体、CSS、IPC 和业务数据均真实。
产品代码没有测试延迟。录屏使用同一方式展示 4 秒启动动画，不能据此判断真实启动耗时。

首轮发现：

- 1024 / 125% 下两行阶段按钮挤压画布；收紧间距并改成单行节点上、名称下，较小视口才换行。
- 早期原生帧的 FontFaceSet 总状态短暂为 `loading`，但所有 ProjectOS Sans FontFace 均已 loaded。
  初始过宽的断言失败保留于 `ui-preview*.txt`。归并重复字体声明、补充实际字体集合等待后，
  最终断言逐项检查首帧字体对象和实际平台字体，而不是把集合状态等同于文字是否已绘制。
- 跨窗口尺寸重新加载会保留已有协作图视口；截图通过现有适应画布按钮取景，没有修改视口持久化。
- 逐张视觉复查发现窄屏详情被待命 Agent 按钮覆盖：二者原先同处第 6 层，后绘制的画布按钮在上。
  提升旅程所在层级至 20（仍低于全局弹层），加入原生命中测试。原图与首次检查保留在
  `diagnostics/`；修复后重新构建、跑八态截图/遮挡检查、录屏并验证打包程序。

最终结果汇总在 `evidence-manifest.json`、`validation/checks.json` 和 `after/checks.json`。
完整命令、原始失败/复查日志、截图与代码随同一提交保存。

最终检查：lint 0 错误 / 24 条既有警告；typecheck 通过；102 个文件、571 项测试通过，4 项外部
可选测试跳过。build、desktop/agent/v12/v13 桌面流程通过。原生专项 164 项通过，8 态共 24 张
对照截图，加 1 张减少动效截图；24 个 axe 状态无违规，逐状态原生合成文字对比达标。
原生录屏、重新打包与 EXE 创建/重启恢复通过。层级修复后的命令见 `validation/rechecks.json`。
